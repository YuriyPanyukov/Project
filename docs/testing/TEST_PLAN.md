# Тест-план для приложения "Менеджер личной коллекции фильмов"

## 1. Объект тестирования
Десктопное приложение «Менеджер личной коллекции» для учета фильмов. Архитектура приложения трехуровневая: Интерфейс (UI), Слой бизнес-логики (Service) и DAO-слой для работы с локальной базой данных SQLite. Приложение позволяет добавлять, редактировать, удалять фильмы, управлять их статусами, жанрами и персонами, а также формировать статистику.

## 2. Цели тестирования
- Проверить корректность выполнения всех CRUD-операций и бизнес-операций, описанных в SERVICE_DESIGN.md.
- Убедиться в надежности валидации входных данных и устойчивости к некорректному вводу.
- Верифицировать целостность данных в SQLite (работа внешних ключей, CHECK-ограничений, транзакций).
- Подтвердить корректную инициализацию БД и сохранение данных между запусками.
- Оценить удобство и адаптивность пользовательского интерфейса.

## 3. Области тестирования
### Функциональное тестирование
- CRUD-операции для сущности Movie (создание, чтение, обновление, удаление).
- Бизнес-операции: добавление фильма со связями, изменение статуса, поиск и фильтрация.
- Формирование аналитики и статистики (DTO: CollectionSummaryDTO, StatusReportDTO и др.).

### Тестирование устойчивости к ошибкам (Negative Testing)
- Ввод пустых строк, строк из пробелов, специальных символов.
- Нарушение ограничений БД (duration <= 0, rating вне диапазона 0-10).
- Передача несуществующих ID (статусов, жанров, персон).

### Тестирование БД и сохранения данных
- Инициализация БД из init.sql при первом запуске.
- Сохранение и чтение данных после перезапуска приложения.
- Каскадное удаление связей (ON DELETE CASCADE).

### Нефункциональное тестирование
- Производительность (время отклика ≤ 1 сек).
- Адаптивность интерфейса и корректность отображения на десктопе.

## 4. Уровни критичности дефектов
- **Критический (Critical)**: Падение приложения, потеря данных, нарушение целостности БД, невозможность сохранить валидный фильм.
- **Значительный (Major)**: Неверный расчет статистики, отсутствие валидации полей, некорректная работа транзакций (частичное сохранение).
- **Незначительный (Minor)**: Опечатки в интерфейсе, неоптимальные сообщения об ошибках.
- **Рекомендация (Trivial)**: Предложения по улучшению UX (автофокус, подсказки).

## 5. Критерии начала тестирования
- Приложение собрано и развернуто в тестовом окружении.
- База данных инициализирована скриптом `init.sql`.
- Внешние ключи включены (`PRAGMA foreign_keys = ON`).

## 6. Критерии завершения тестирования
- Выполнено 100% тест-кейсов с позитивными сценариями.
- Выполнено ≥90% тест-кейсов с негативными и граничными сценариями.
- Все дефекты уровня Critical и Major устранены.
- Подтверждено соответствие всем критериям приёмки из BRIEF.md.

## 7. Требования к тестовым данным
- **Предзаполненные данные (из init.sql)**: Фильмы "Начало" (id=1), "Дюна" (id=2); Статусы (id=1,2,3); Жанры (id=1..4); Персоны (id=1..3).
- **Дополнительные данные**: Фильмы с NULL оценкой, несуществующие ID (999), строки из пробелов, граничные значения (rating=0, rating=10, duration=1).
