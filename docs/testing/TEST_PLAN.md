# Тест-план для приложения «Менеджер личной коллекции (фильмы)»

## 1. Объект тестирования
Объектом тестирования является приложение «Менеджер личной коллекции (фильмы)», предназначенное для каталогизации, структурирования и ведения учета домашних фильмов, включая отслеживание статусов просмотра, выставление личных оценок, управление жанрами и режиссерами/актерами. Вся серверная бизнес-логика и DAO-слой работы с СУБД SQLite считаются реализованными.

## 2. Цели тестирования
* Проверить корректность выполнения всех базовых CRUD-операций над фильмами через класс `MovieDAO`.
* Убедиться в правильности обработки связей один-ко-многим и многие-ко-многим согласно ER-диаграмме базы данных.
* Проверить соответствие логики работы приложения заявленным Use Cases (добавление, поиск по фильтрам, расчет сквозной аналитики).
* Подтвердить стабильность приложения при обработке некорректного пользовательского ввода и граничных значений.

## 3. Области тестирования
* **Функциональное тестирование:** Проверка методов вывода полного списка фильмов (`getAll`), получения карточки по ID (`getById`), создания новых записей (`insert`), обновления оценок/статусов (`update`) и удаления элементов (`delete`).
* **Тестирование интерфейса и Use Cases:** Проверка работы поисковой строки, боковой панели фильтрации (по статусам и звездной оценке), формы добавления фильма и корректности рендеринга графиков на вкладке «Аналитика».
* **Тестирование устойчивости к ошибкам (Защита от ошибок):** Валидация незаполненного поля «Название» при сохранении, проверка недопустимости отрицательной длительности фильма, контроль целостности внешних ключей.
* **Тестирование производительности:** Время отклика интерфейса SQLite при получении списков и переключении вкладок не должно превышать 1 секунды.
* **Тестирование инициализации данных:** Проверка развертывания таблиц `movies`, `statuses`, `genres`, `movie_genres`, `persons`, `movie_persons` при первичном запуске.

## 4. Уровни критичности дефектов
* **Критический (Critical):** Ошибки в SQL-синтаксисе, падение методов `MovieDAO` с генерацией исключений, блокировка базы данных SQLite, потеря данных коллекции, обходные пути отсутствуют.
* **Значительный (Major):** Функция работает, но нарушает логику ТЗ или ER-диаграммы (например, при удалении фильма остаются висеть записи в таблицах связей `movie_genres`, некорректно рассчитывается средняя оценка на экране аналитики).
* **Незначительный (Minor):** Визуальные дефекты на макетах (съехавший элемент формы, неверное выравнивание плашек), орфографические ошибки в интерфейсе на русском языке, неконсистентный формат логов.
* **Рекомендация (Suggestion):** Предложения по рефакторингу сырых SQL-запросов внутри `movie_dao.py`, добавление индексов для ускорения поиска.

## 5. Критерии начала тестирования
* База данных SQLite автоматически инициализируется встроенным SQL-скриптом из `init.sql` при первом старте.
* Класс `MovieDAO` содержит методы, готовые к изолированному вызову.
* Доступен файл конфигурации подключения `database.py`.

## 6. Критерии завершения тестирования
* Успешно пройдены все тест-кейсы, описанные в перечне `TEST_CASES.md`.
* Процент успешных тест-кейсов (Pass Rate) составляет 100% для блокирующих и критических функций.
* Все дефекты уровней «Критический» и «Значительный» полностью устранены и перепроверены.

## 7. Требования к тестовым данным
Для полноценного проведения тестирования в SQLite БД должны быть предзаполнены:
* В таблице `statuses` — справочные записи: `1 - В планах`, `2 - В процессе`, `3 - Завершено`, `4 - Брошено`.
* В таблице `genres` — базовые жанры (например: Комедия, Драма, Фантастика).
* В таблице `persons` — не менее 3 представителей (режиссеры, актеры).
* Для тестов аналитики в таблицу `movies` должно быть добавлено не менее 5 тестовых фильмов с заполненными полями длительности, года выпуска и личного рейтинга.
