# Перечень тест-кейсов для итогового тестирования приложения

## Группа 1: Инициализация БД и целостность структуры данных

### Тест-кейс SYS-01: Создание структуры БД при первом запуске из SQL-скрипта
* **Связанная функция:** Инициализация БД / `database.py`
* **Приоритет:** Высокий
* **Предусловия:** Файл базы данных SQLite отсутствует на диске (первый запуск).
* **Тестовые данные:** Файл инициализации структуры `init.sql`.
* **Шаги выполнения:**
  1. Запустить приложение.
  2. Открыть созданный файл БД через внешнюю утилиту (например, DB Browser for SQLite) и проверить схему данных.
* **Ожидаемый результат:** Все 6 таблиц (`movies`, `statuses`, `genres`, `movie_genres`, `persons`, `movie_persons`) успешно созданы. Связи внешних ключей настроены строго по ER-диаграмме.

### Тест-кейс SYS-02: Обеспечение каскадного удаления связей (Foreign Keys)
* **Связанная функция:** Работа базы данных / Удаление элементов
* **Приоритет:** Высокий
* **Предусловия:** В БД создан фильм с ID=10, для которого в `movie_genres` и `movie_persons` добавлены соответствующие связующие строки.
* **Тестовые данные:** ID удаляемого фильма = 10.
* **Шаги выполнения:**
  1. Вызвать метод `MovieDAO().delete(10)`.
  2. Выполнить прямые поисковые SQL-запросы в таблицы `movie_genres` и `movie_persons` по условию `movie_id = 10`.
* **Ожидаемый результат:** Метод возвращает `True`. В связующих таблицах `movie_genres` и `movie_persons` автоматически очистились все строки, содержащие `movie_id = 10`. Нарушений ограничений внешнего ключа не возникает.

## Группа 2: Изолированное тестирование методов класса MovieDAO (CRUD)

### Тест-кейс DAO-01 (Позитивный): Добавление валидного фильма в личную коллекцию
* **Связанная функция:** `MovieDAO.insert(self, movie: Movie) -> bool`
* **Приоритет:** Высокий
* **Предусловия:** В таблице `statuses` существует запись с `id=1` («В планах»).
* **Тестовые данные:** Объект `Movie(title="Пила 1", duration=103, rating=6.0, status_id=1)`.
* **Шаги выполнения:**
  1. Вызвать метод `MovieDAO().insert(movie)`.
  2. Проверить возвращаемое значение метода.
  3. Проверить состояние переданного объекта `movie`.
* **Ожидаемый результат:** Метод возвращает `True`. В поле `movie.id` автоматически записывается корректный числовой идентификатор, присвоенный СУБД SQLite.

### Тест-кейс DAO-02 (Негативный): Попытка вставки фильма с незаполненным именем
* **Связанная функция:** `MovieDAO.insert(self, movie: Movie) -> bool`
* **Приоритет:** Высокий
* **Предусловия:** База данных запущена. По ТЗ запрещено сохранять элементы без названия.
* **Тестовые данные:** Объект `Movie(title="", duration=120, rating=5.0, status_id=2)`.
* **Шаги выполнения:**
  1. Вызвать метод `MovieDAO().insert(movie)`.
* **Ожидаемый результат:** Метод возвращает `False`, в блоке `except` отрабатывает вывод системного сообщения "Ошибка добавления фильма...". Запись в таблице `movies` не создается.

### Тест-кейс DAO-03 (Граничный): Валидация корректности числового поля длительности (duration)
* **Связанная функция:** `MovieDAO.insert(self, movie: Movie) -> bool`
* **Приоритет:** Средний
* **Предусловия:** База данных активна. ТЗ запрещает указывать отрицательные значения количества/параметров.
* **Тестовые данные:** Объект `Movie(title="Отрицательное время", duration=-15, rating=4.0, status_id=1)`.
* **Шаги выполнения:**
  1. Попытаться вставить переданный тестовый объект через метод `insert()`.
* **Ожидаемый результат:** Запрос отклоняется (на уровне проверки бэкенда или через CHECK-constraint уровня СУБД), метод возвращает `False`, невалидные данные в SQLite не попадают.

### Тест-кейс DAO-04 (Позитивный): Чтение полной коллекции элементов на одном экране
* **Связанная функция:** `MovieDAO.getAll(self) -> list[Movie]`
* **Приоритет:** Высокий
* **Предусловия:** В таблице `movies` содержится ровно 3 записи о фильмах.
* **Тестовые данные:** База данных с 3 фильмами.
* **Шаги выполнения:**
  1. Вызвать метод `MovieDAO().getAll()`.
  2. Посчитать длину возвращаемого списка и проверить типы данных.
* **Ожидаемый результат:** Метод возвращает список, содержащий ровно 3 объекта класса `Movie`. Элементы отсортированы по возрастанию `id` (`ORDER BY id`).

### Тест-кейс DAO-05 (Позитивный): Изменение статуса просмотра и обновление оценки фильма
* **Связанная функция:** `MovieDAO.update(self, movie: Movie) -> bool`
* **Приоритет:** Высокий
* **Предусловия:** В коллекции уже сохранен фильм с `id=1`, имеющий `status_id=1` («В планах») и `rating=6.0`.
* **Тестовые данные:** Модифицированный объект `Movie(id=1, title="Пила 1", duration=103, rating=8.5, status_id=3)`.
* **Шаги выполнения:**
  1. Вызвать метод `MovieDAO().update(movie)`.
  2. Проверить возвращаемое булево значение.
  3. Извлечь эту же запись из БД заново через `MovieDAO().getById(1)`.
* **Ожидаемый результат:** Метод возвращает `True`, `cursor.rowcount > 0`. Повторно извлеченный объект содержит обновленный статус `3` («Завершено») и оценку `8.5`.

## Группа 3: Проверка сценариев использования (Use Cases) и фильтрации интерфейса

### Тест-кейс UC-01: Поиск конкретного фильма по ключевым словам через поисковую строку
* **Связанная функция:** Поисковая строка / Фильтрация коллекции
* **Приоритет:** Высокий
* **Предусловия:** В коллекции находятся фильмы с названиями: "Пила 1", "Пила 2", "Начало", "Интерстеллар".
* **Тестовые данные:** Поисковый запрос string = `"Пила"`.
* **Шаги выполнения:**
  1. Ввести в поисковую строку интерфейса ключевое слово "Пила".
  2. Нажать кнопку поиска/применить фильтр.
* **Ожидаемый результат:** В результирующей таблице отображаются только два элемента: "Пила 1" и "Пила 2". Остальные фильмы скрыты.

### Тест-кейс UC-02: Одновременная фильтрация по статусу контента и личному рейтингу
* **Связанная функция:** Панель фильтрации
* **Приоритет:** Высокий
* **Предусловия:** В системе есть фильмы со статусом «Завершено» и оценками 4.0, 4.5, 9.0, а также фильмы со статусом «В процессе».
* **Тестовые данные:** Фильтр: Статус = `«Завершено»`, Рейтинг = `4 звезды (оценки от 4.0 до 4.9)`.
* **Шаги выполнения:**
  1. На панели фильтров отметить чекбокс «Завершено».
  2. Выбрать фильтр рейтинга в 4 звезды.
  3. Нажать кнопку «Применить».
* **Ожидаемый результат:** На главном экране отображаются исключительно фильмы "Пила 2" (оценка 4.5) и "Пила 3" (оценка 4.0). Фильмы со статусом «В процессе» или другими оценками отсеиваются.

### Тест-кейс UC-03: Отображение заглушки при отсутствии совпадений по фильтрам
* **Связанная функция:** Обработка пустых результатов интерфейса
* **Приоритет:** Средний
* **Предусловия:** В коллекции нет ни одного фильма со статусом «В процессе».
* **Тестовые данные:** Фильтр: Статус = `«В процессе»`.
* **Шаги выполнения:**
  1. Установить на панели фильтрацию по статусу «В процессе».
  2. Нажать кнопку «Применить».
* **Ожидаемый результат:** Таблица со списком фильмов очищается. На экране появляется информативное текстовое сообщение: «В вашей коллекции пока нет фильмов со статусом "В планах"» (или соответствующее выбранному пустому фильтру) и отображается активная кнопка сброса установленных фильтров.

### Тест-кейс UC-04: Расчет сквозной аналитики коллекции на специальной вкладке
* **Связанная функция:** Модуль аналитики / Группировка данных статистики
* **Приоритет:** Высокий
* **Предусловия:** В БД добавлено 5 фильмов с оценками: 6.0, 4.5, 4.0, 5.5, 7.0 (Сумма = 27.0, среднее = 5.4).
* **Тестовые данные:** Набор из 5 заполненных записей в таблице `movies`.
* **Шаги выполнения:**
  1. Перейти на вкладку интерфейса «Аналитика».
  2. Зафиксировать числовые показатели в блоках «Всего фильмов» и «Средняя оценка».
* **Ожидаемый результат:** В блоке общего количества отображается цифра `5`. В поле средней оценки отображается точное рассчитанное значение `5.4 ★`. На графиках распределения по статусам данные сгруппированы корректно.
