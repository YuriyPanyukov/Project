# UML-диаграммы программного продукта
## «Менеджер личной коллекции фильмов» (Python + SQLite, архитектура UI → Service → DAO)

Подготовлены три диаграммы уровня UML 2.x, описывающие программный продукт **целиком**.
Исходный текст каждой диаграммы — в файлах `src/*.puml` (PlantUML), итоговые изображения — в PNG.

---

## 1. Диаграмма составной структуры программы (`01_composite_structure.png`)

**Тип:** Structural diagram → Composite Structure Diagram.
**Правила оформления:** система изображается как большой прямоугольник с частью (part) внутри;
внешние элементы — актёр и среда запуска; компоненты обозначаются нотацией «прямоугольник
с двумя маленькими прямоугольниками»; связи: композиция подсистем (закрашенный ромб),
зависимости (пунктир), реализации портов/интерфейсов (стрелки со стереотипом вызова методов);
хранилище — нотация базы данных (цилиндр).

Составные части продукта:

| Часть (part) | Реализация в коде | Роль |
|---|---|---|
| Подсистема представления | `main.py`, консольный UI | ввод команд, вывод результатов |
| Подсистема бизнес-логики | `services/movie_service.py` (`MovieService`, `BusinessRuleError`, `NotFoundError`) | валидация, бизнес-правила, транзакции |
| Подсистема доступа к данным | `movie_dao.py` (`MovieDAO`), `stats_dao.py` (`StatsDAO`) | CRUD и агрегирующие SQL-запросы |
| Подсистема доменных моделей | `models.py` (`Movie`, `CollectionSummaryDTO`, `PersonStatsDTO`, `StatusReportDTO`, `GenreReportDTO`) | DTO/сущности предметной области |
| Подсистема подключения к БД | `database.py` (`get_connection()`) | соединения sqlite3, PRAGMA foreign_keys |
| Хранилище | `movies.db` (`init.sql`: statuses, genres, persons, movies, movie_genres, movie_persons) | персистентное хранение |

## 2. Диаграмма состояний программы (`02_state_machine.png`)

**Тип:** Behavioral diagram → State Machine Diagram.
**Правила оформления:** начальное состояние — закрашенный круток `[*]`, финальное — кружок
с точкой; состояния — скруглённые прямоугольники с секциями `entry / do / exit`; переходы —
стрелки с событием и guard-условием `[условие]`; составные (ортогональные не используются)
состояния декомпозируются вложенными диаграммами состояний.

Модель жизненного цикла программы целиком:

- **Инициализация** (создание/открытие БД, применение `init.sql`, загрузка коллекции);
- **Главное меню** — рабочее (do-) состояние, из которого выполняются все сценарии;
- Составные состояния операций: **Добавление фильма** (подсостояние ошибки валидации),
  **Просмотр и поиск**, **Редактирование**, **Изменение статуса просмотра**
  (конечный автомат фильма: «В планах» → «В процессе» → «Завершено»),
  **Удаление** (ветвление по подтверждению), **Аналитика**;
- Состояние обработки ошибок (`NotFoundError`, `BusinessRuleError`) с возвратом в меню;
- **Завершение** (закрытие соединений, сохранение `movies.db`) и финальное состояние.

## 3. Диаграмма обзора взаимодействия (`03_communication_overview.png`)

**Тип:** Behavioral diagram → Interaction Overview Diagram, построенная на основе
Communication Diagram (диаграмма коммуникации/объектов).
**Правила оформления:** узлы — экземпляры объектов в нотации `:Класс`; линии — связи
ассоциации; сообщения — пронумерованные стрелки у линий (порядковый номер = хронология
обмена); обратные ответы — пунктирные стрелки; синхронные вызовы — сплошные стрелки.

Хронология сквозного взаимодействия для всех основных сценариев продукта
(добавление, редактирование, удаление, поиск/фильтрация, смена статуса, аналитика):

1. Пользователь → `:ConsoleUI` — команда;
2. `:ConsoleUI` → `:MovieService` — вызов метода сервиса;
3. `:MovieService` → `:MovieService` — валидация бизнес-правил;
4–5. `:MovieService` → `:get_connection()` → SQLite — открытие соединения и транзакции;
6–7. проверка справочников через `:StatsDAO`;
8–9. CRUD-запрос через `:MovieDAO`;
10–11. замена связей (жанры/персоны) или статистические запросы через `:StatsDAO`;
12–13. `COMMIT`/`ROLLBACK`, получение строк из БД;
14–17. маппинг результата в `Movie`/DTO и возврат в сервис;
18–19. возврат результата (или исключения) в интерфейс и пользователю.

## Как воспроизвести / отредактировать

```bash
java -jar plantuml.jar -tpng docs/uml/src/*.puml
```

Файлы `.puml` открываются в любом редакторе PlantUML (IntelliJ, VS Code,
https://www.plantuml.com/plantuml, https://plantuml-erlang.net и т. п.).
