## Общие сведенья(1)
#### Название продукта:Менеджер личной коллекции (фильмы)
#### Краткое описание: программа, которая помогает структурировать, вести учет и наводить порядок в ваших домашних фильмов
#### Целевая аудитория:Это люди, для которых собирательство - серьезное хобби. Их коллекция постоянно растет, и они гордятся ею.

## Функциональные требования(2)
#### Обязательные: 
Пользователь может добавлять новый элемент в коллекцию (указав название, тип контента:(фильм).
Пользователь может просматривать полный список всех добавленных элементов своей коллекции на одном экране.
Пользователь может редактировать информацию о любом элементе (изменять статус, ставить личную оценку).
Пользователь может удалять элементы из своей коллекции.
Пользователь может фильтровать коллекцию по типу контента (отобразить только книги, только фильмы или только игры).
Пользователь может менять статус прохождения/потребления элемента (например: «В планах», «В процессе», «Завершено»).
Пользователь может искать конкретный элемент в своей коллекции по ключевым словам в названии через поисковую строку.
Дополнительные:
Пользователь может отмечать, кому и когда он отдал физическую копию вещи (книгу или диск), с фиксацией даты возврата.
Пользователь может автоматически заполнять данные о книге/фильме/игре по названию через интеграцию с внешним API.

## Нефункциональные требования(3)
#### Язык интерфейса: русский.
#### Производительность: время отклика интерфейса — не более 1 секунды при стандартных операциях.
#### Хранение данных: локально в файле БД (SQLite), сеть не используется.
#### Защита от ошибок: нельзя сохранить рецепт без названия, нельзя указать отрицательное количество ингредиента, нельзя удалить ингредиент, который используется в рецепте (без подтверждения).
#### Инициализация БД: при первом запуске приложение само создаёт таблицы из встроенного SQL-скрипта.

## Сценарии использования (Use Cases)(6)
Сценарий 1: Добавление нового элемента в коллекцию
Актёр: Пользователь
Предусловие: Пользователь авторизован в системе и находится в разделе «Моя коллекция».
Основной поток:
   1. Пользователь нажимает кнопку «Добавить элемент».
   2. Система отображает форму ввода данных (название, тип: книга/фильм/игра, автор/режиссер/разработчик, год издания, статус).
   3. Пользователь заполняет обязательные поля формы и нажимает кнопку «Сохранить».
   4. Система проверяет корректность введенных данных.
   5. Система сохраняет элемент в базу данных.
   6. Система выводит сообщение об успешном добавлении и обновляет список коллекции.
   Альтернативный поток: Пользователь не заполнил обязательное поле «Название». Система подсвечивает пустое поле красным цветом, выводит предупреждение «Название обязательно для заполнения» и блокирует сохранение до исправления ошибки.

Сценарий 2: Поиск элемента в коллекции по фильтрам
Актёр: Пользователь
Предусловие: В коллекции пользователя уже есть добавленные элементы; пользователь находится на главном экране списка коллекции.
Основной поток:
   1. Пользователь нажимает на кнопку «Фильтры».
   2. Система отображает панель фильтрации (по типу: книга/фильм/игра, по статусу: «В планах»/«В процессе»/«Завершено»).
   3. Пользователь выбирает тип «Фильмы» и статус «В планах», затем нажимает «Применить».
   4. Система обрабатывает запрос и фильтрует базу данных пользователя.
   5. Система отображает на экране только те элементы, которые соответствуют выбранным критериям.
   Альтернативный поток: Элементы с заданными критериями фильтрации не найдены. Система отображает сообщение «В вашей коллекции пока нет фильмов со статусом "В планах"» и предлагает сбросить фильтры.


Сценарий 3: Просмотр аналитики и статистики коллекции
Актёр: Пользователь
Предусловие: Пользователь находится на главной странице системы, в его коллекции добавлено не менее 5 различных элементов с выставленными оценками и статусами.
Основной поток:
1. Пользователь переходит во вкладку «Аналитика».
2. Система делает агрегирующие запросы к базе данных.
3. Система рассчитывает общее количество элементов в коллекции и их среднюю оценку.
4. Система группирует данные по таблице statuses и выводит распределение элементов по статусам («В планах», «В процессе», «Завершено/Пройдено», «Брошено»).
5. Система анализирует таблицы связей и формирует списки «Топ-N авторов» и «Топ-N жанров» на основе количества элементов или средних оценок.
6. Система визуализирует полученные метрики на экране в виде графиков и сводных таблиц.
Альтернативный поток: В базе данных пользователя полностью отсутствуют элементы. Система выводит сообщение «Недостаточно данных для формирования аналитики. Добавьте первые элементы в коллекцию и выставьте им оценки».


## Критерии приёмки(7)
1)Авторизация: Пользователь может успешно войти в систему под своей учётной записью, при этом незарегистрированные пользователи не имеют доступа к личной коллекции.
2)Добавление элементов: Реализована возможность добавления новых элементов с обязательным указанием названия и типа контента (книга, фильм или игра).
3)Классификация по категориям: В интерфейсе коллекции реализовано чёткое разделение элементов по типам (книги / фильмы / игры).
4)Фильтрация данных: Пользователь может отфильтровать список коллекции одновременно по типу контента и по текущему статусу.
5)Корректность пустых результатов: При отсутствии подходящих под фильтры элементов система выводит информативное сообщение о том, что ничего не найдено, и предлагает сбросить фильтры.
6)Управление статусами: Доступно изменение статуса изучения контента («В планах», «В процессе», «Завершено/Пройдено», «Брошено») для любого элемента коллекции.
7)Сохранение изменений: Любые изменения данных элемента (оценки, статусы, заметки) успешно перезаписываются в базе данных и актуализируются на экране.
8)Адаптивность интерфейса: Главный экран коллекции корректно отображается и остаётся читаемым как на десктопных мониторах.
