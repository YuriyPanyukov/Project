# Менеджер личной коллекции (фильмы): слой бизнес-логики

Реализация задания по проекту на Python + SQLite. Бизнес-логика находится в `services/`,
а SQL-запросы — в `dao.py`. Консольные тесты лежат в `tests/test_movie_service.py`.

## Структура

```text
.
├── services/
│   ├── __init__.py
│   └── movie_service.py
├── tests/
│   └── test_movie_service.py
├── database.py
├── dao.py
├── init.sql
├── run_tests.py
└── README.md
```

## Что реализовано

- добавление фильма с проверкой полей и транзакцией;
- редактирование фильма и связей с жанрами/персонами;
- удаление фильма;
- поиск по названию, фильтрация по жанру, статусу и оценке, сортировка;
- подтверждение перед удалением и корректная отмена удаления;
- повторное назначение текущего статуса обрабатывается как информационный сценарий;
- размер рейтингов статистики ограничен диапазоном от 1 до 20;
- смена статуса;
- статистика коллекции, популярные персоны и жанры;
- проверки обязательных полей, продолжительности, рейтинга, статуса, жанров, персон и ролей;
- понятные исключения `BusinessRuleError` и `NotFoundError`;
- откат составных операций SQLite при ошибках;
- консольные тесты успешных и ошибочных сценариев.

## Запуск

Требуется Python 3.10+; сторонние библиотеки не нужны.

Из корня проекта выполните:

```bash
python -m unittest discover -s tests -v
```

или:

```bash
python -m unittest discover -s tests -v
```

Тесты используют временную базу `:memory:` и не изменяют вашу рабочую `movies.db`.

## Подключение к существующему репозиторию

1. Скопируйте папку `services/` и `tests/` в свой репозиторий.
2. Сверьте методы `MovieDAO` и `StatsDAO` в вашем проекте с методами из `dao.py`.
3. Если DAO уже реализован, не заменяйте его: перенесите методы `replace_movie_links`,
   `get_movie_links`, `find_status_id` и `exists_ids` в ваш DAO или адаптируйте сервис к
   существующим названиям.
4. Сохраните таблицы `movies`, `statuses`, `persons`, `movie_persons`, `genres`, `movie_genres`.
5. Добавьте файлы в GitHub и запустите тесты перед сдачей.

## Примечание по схеме

В этой версии таблица `movies` соответствует имеющейся схеме: `id`, `title`, `duration`,
`rating`, `status_id`. Поля года выпуска нет. Связи с персонами используют `persons`,
`movie_persons` и поле `role`.
